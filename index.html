odpc-platform-x/php-oidc-odpc-x-idp

Reusable Laravel OIDC (authorization-code + PKCE) package against the ODPCX IdP Link, on top of Laravel's own session guard.

Overview

Overview

แพ็กเกจนี้ทำหน้าที่เป็น auth module สำเร็จรูปสำหรับแอป Laravel ที่ต้องล็อกอินผ่าน ODPCX IdP Link ด้วย OAuth2 authorization-code flow (PKCE) แล้วใช้ session guard ของ Laravel เองแทนการ hand-roll JWT cookie — session cookie, guard, และ auth middleware มาฟรีจาก Laravel อยู่แล้ว ตัวแพ็กเกจเป็น generic core เท่านั้น — ไม่มี role, ไม่มี Eloquent model, ไม่มี JIT-provisioning logic ผูกมาด้วย — ฝั่ง host แอปต้อง implement AuthUserService หนึ่งอินเทอร์เฟซเพื่อเชื่อมกับ user store ของตัวเอง

Browser
/auth/login
ODPCX IdP Link

Laravel session

ผู้ใช้ล็อกอินผ่าน ODPCX IdP Link แล้วได้รับ token กลับมาเป็น Laravel session ผ่าน Auth::guard()->login()

หลังจากนั้น ทุก request ที่ต้อง auth จะอาศัย Laravel session cookie ตามปกติ — auth middleware ตรวจสอบ session แล้ว GET /auth/me คืน Auth::user() เป็น JSON

Setup

Requirements

  • PHP >= 8.2
  • Laravel 11 or 12 — uses illuminate/support, illuminate/http, illuminate/auth, illuminate/routing
  • firebase/php-jwt ^6.10 — installed automatically; used for RS256 id_token verification against the IdP's JWKS
  • Session middleware — this package's routes run behind Laravel's web middleware group by default, which already includes session + CSRF handling

Install

composer config repositories.odpcx-idp vcs git@github.com:odpc-platform-x/php-oidc-odpc-x-idp.git
composer require odpc-platform-x/php-oidc-odpc-x-idp

Laravel package auto-discovery registers OdpcxAuthServiceProvider automatically — no manual provider registration needed.

Get running

Quickstart

  1. Implement AuthUserService

    นี่คือจุดเดียวที่ host แอปต้อง implement เอง — JIT-provisioning, Eloquent upsert, role logic ทั้งหมดไปอยู่ที่นี่

    use Illuminate\Contracts\Auth\Authenticatable;
use OdpcPlatformX\PhpOidcOdpcXIdp\Contracts\AuthUserService;

class MyAuthUserService implements AuthUserService
{
    public function onLogin(array $claims): Authenticatable
    {
        // your own Eloquent upsert / JIT role provisioning / season logic goes here
        return User::updateOrCreate(
            ['idp_sub' => $claims['sub']],
            ['email' => $claims['email'], 'name' => $claims['name']],
        );
    }
}

  2. Bind it in your AppServiceProvider

    use OdpcPlatformX\PhpOidcOdpcXIdp\Contracts\AuthUserService;

public function register(): void
{
    $this->app->bind(AuthUserService::class, MyAuthUserService::class);
}

  3. Set env vars

    # Official ODPCX IdP Link (frontend: https://idp.odpcx.com)
ODPCX_OIDC_ISSUER=https://api.idp.odpcx.com
ODPCX_OIDC_CLIENT_ID=...
ODPCX_OIDC_CLIENT_SECRET=...
ODPCX_OIDC_REDIRECT_URI=https://your-app.example.com/auth/callback
ODPCX_OIDC_POST_LOGOUT_REDIRECT_URI=https://your-app.example.com

    Discovery document: https://api.idp.odpcx.com/.well-known/openid-configuration

    This wires up GET /auth/login, GET /auth/callback, POST /auth/logout, GET /auth/me behind the web middleware group. Layer your own authorization (roles, policies) on top of the auth middleware — that's intentionally not part of this package.

Reference

Routes

EndpointBehavior
GET {prefix}/loginStores PKCE state/nonce/verifier in the session, redirects (302) to the IdP. 503 if discovery is unavailable.
GET {prefix}/callbackVerifies state, exchanges code, verifies id_token, calls onLogin(), logs in via the guard, redirects to intended(). 401 on state/nonce mismatch, 500 if onLogin() throws.
POST {prefix}/logout (auth)Logs out, invalidates session, returns { "logoutUrl": "..." } for the client to navigate to.
GET {prefix}/me (auth)Returns Auth::user() as JSON. 401 if unauthenticated.

Resilience

Discovery caching — no restart needed on IdP recovery

Discovery and JWKS documents are cached for discovery_ttl seconds, but only on success. A failed fetch aborts with 503 ("OIDC provider is not configured or discovery is unavailable") and is never cached — the very next request retries from scratch. If the IdP is temporarily down, the app recovers automatically once it's back, no restart required.

Read before you rely on this

Caveats

  • No refresh-token flow. Once the Laravel session expires, the user must log in again via GET {prefix}/login.
  • No role/permission guards included. Any authorization beyond "is this a valid session" is a host concern — layer your own on top of the auth middleware.
  • No IdP call at boot. Discovery only ever happens lazily on the first request that needs it (login/callback), so the app still boots even if the IdP is unreachable.
